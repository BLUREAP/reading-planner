# 📘 Техническое задание (ТЗ)
## На разработку веб-приложения "Reading Planner"

### 1. Общее описание
**Название проекта:** Reading Planner (Планировщик чтения).  
**Цель:** Создание веб-приложения для студентов и читателей, позволяющего планировать чтение книг, отслеживать прогресс в реальном времени и анализировать темп чтения с помощью интерактивных графиков.

### 2. Функциональные требования
Система должна предоставлять следующий функционал для авторизованных пользователей:

1.  **Управление аккаунтом:**
    *   Вход в систему (Логин/Пароль).
    *   Безопасный выход из системы.
2.  **Управление библиотекой (CRUD книг):**
    *   Просмотр списка всех добавленных книг.
    *   Добавление новых книг через форму.
    *   Удаление книг из списка.
3.  **Интеграция с внешними API:**
    *   Автоматическое заполнение полей "Автор" и "Количество страниц" при добавлении книги через Google Books API.
    *   Обработка ошибок API (в случае недоступности сервиса) с возможностью ручного ввода данных.
4.  **Ведение дневника чтения:**
    *   Создание записей (сессий) о прочитанных страницах с указанием даты.
5.  **Аналитика и Визуализация:**
    *   Отображение текущего прогресса в процентах (Progress Bar).
    *   Построение интерактивного линейного графика (Plotly), отображающего динамику чтения от начала до текущей даты.
    *   Расчет накопительного итога страниц с использованием библиотеки Pandas.

### 3. Стек технологий
*   **Backend:** Python 3.14, Django 4.2.
*   **Frontend:** HTML5, CSS3, Bootstrap 5 (адаптивная верстка).
*   **База данных:** SQLite (локально), PostgreSQL (на хостинге PythonAnywhere).
*   **Аналитика:** Pandas (обработка DataFrame, расчет `cumsum`).
*   **Визуализация:** Plotly (построение графиков).
*   **API:** Google Books API (для метаданных книг).
*   **Контроль версий:** Git, GitHub.

### 4. Структура базы данных
Приложение использует три основные сущности (Модели):

1.  **Book (Книга):**
    *   `title`: Название книги (CharField).
    *   `author`: Автор книги (CharField).
    *   `total_pages`: Общее количество страниц (IntegerField).
    *   `deadline`: Дедлайн для чтения (DateField).
    *   `external_id`: ID книги из Google Books (CharField, уникальный).
    *   `user`: Владелец книги (ForeignKey -> User).

2.  **ReadingSession (Сессия чтения):**
    *   `book`: Связь с книгой (ForeignKey -> Book).
    *   `date`: Дата чтения (DateField).
    *   `pages_read`: Количество прочитанных страниц за сессию (IntegerField).

3.  **User (Пользователь):**
    *   Используется стандартная модель Django `auth.User`.

### 5. Логика работы модуля аналитики
Аналитический движок работает по следующему алгоритму:
1.  Запрашивает из БД все сессии чтения для конкретной книги, отсортированные по дате.
2.  Преобразует данные в `pandas.DataFrame`.
3.  Вычисляет столбец `cumulative_pages` (накопительный итог прочитанного) через метод `.cumsum()`.
4.  Рассчитывает процент выполнения плана: `(текущее_количество / всего_страниц) * 100`.
5.  Генерирует HTML-код интерактивного графика через `plotly.express` и передает его в контекст шаблона Django.

### 6. Обработка ошибок и ограничения
*   При превышении лимита запросов к Google Books API (ошибка 429 Too Many Requests), система не прерывает работу, а сохраняет книгу с данными, введенными пользователем вручную, и выводит предупреждение.
*   Все пользовательские данные изолированы: пользователь видит только свои книги и свою статистику (используется `request.user`).

### 7. Сценарии использования
1.  **Добавление книги:**
    *   Пользователь переходит на страницу "/add/".
    *   Вводит название книги и дедлайн.
    *   Система отправляет запрос к Google Books API.
    *   Если ответ успешный -> заполняет поля "Автор" и "Страницы".
    *   Пользователь нажимает "Сохранить".
2.  **Просмотр прогресса:**
    *   Пользователь кликает на карточку книги.
    *   Загружается детальная страница.
    *   Отображается прогресс-бар и график.
    *   Пользователь вводит в форму "Отметить прочитанное" 50 страниц.
    *   После перезагрузки график обновляется, показывая новую точку на оси Y.

### 8. Деплой
Проект развернут на облачном хостинге **PythonAnywhere**.
*   Используется WSGI-сервер.
*   Настроена раздача статических файлов.
*   Окружение изолировано (Virtualenv).
